# Негрелочка: прототип

FastAPI + SQLite (SQLAlchemy) на бэкенде, React (Vite) на фронтенде.

## Как устроен конкурс

Фазы идут строго по порядку: `draft → submission → voting → results`. Назад пути нет.
Фазу переключает организатор вручную, либо она переключается сама по дедлайну.

| Фаза | Участник | Видит |
|---|---|---|
| draft | ничего | тему не видит |
| submission | пишет и правит свой рассказ (с базовым форматированием) и дисклеймер | только свой рассказ |
| voting | читает чужие работы, ставит оценки и звёзды | работы под случайными номерами, **без авторов** |
| results | смотрит итоги | топы, оценки, **авторов** |

**Оценивание.** Пять шкал по 1–5: общее впечатление, верность теме, красота слога, «светлость» (1 — тёмный рассказ, 5 — светлый), авантюризм.
Оценка рассказа — это сразу все пять шкал (можно переоценить, пока идёт фаза оценивания).
У каждого участника **3 звезды**, одной звездой отмечается один рассказ; звезду можно забрать и отдать другому.
Свой рассказ виден в общем списке (с пометкой «ваш») и доступен для чтения, но оценивать, отмечать звездой, рецензировать и заполнять по нему опросник нельзя.

**Опросник** (необязательный, только для статистики): жанр, сеттинг, пол главного героя, «про детей / про животных / кто-то умер / есть пушки». В финале показываются только агрегаты по рассказу и по конкурсу; ответы конкретных читателей наружу не отдаются.

**Обязательное при оценивании:** оценить все чужие работы и раздать все 3 звезды (если чужих работ меньше трёх, достаточно отметить каждую). Авторов, не выполнивших это, финал показывает красным с пояснением («оценил 2 из 4 работ, раздал 1 из 3 звёзд»); их рассказы остаются доступными для чтения во вкладке «Все работы», но **в топы и к победителям не попадают** (места остальных пересчитываются без них).

**Топы** считаются отдельно: по каждой из пяти шкал (средний балл; при равенстве выше тот, у кого больше оценок;
равные места общие: 1, 2, 2, 4) и отдельно по звёздам. Общего «победителя за всё» нет: в каждой номинации свой победитель.

**Правило голосования.** По умолчанию оценивать могут только те, кто сам прислал рассказ
(`voters_must_submit`; организатор выбирает при создании конкурса).

**Регистрация** только по одноразовой ссылке `/register/<uuid>`, которую создаёт организатор.

## Запуск

```bash
# 1. бэкенд
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
export ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='сложный-пароль'   # организатор создаётся при первом запуске
uvicorn app.main:app --reload            # http://localhost:8000  (документация API: /docs)

# 2. фронтенд (в другом терминале)
cd frontend
npm install
npm run dev                              # http://localhost:5173, /api проксируется на :8000
```

Один сервис вместо двух: `npm run build` в `frontend/`, после этого FastAPI сам отдаёт `frontend/dist`.

Тесты: `cd backend && pytest`.

Первые шаги: войдите организатором → «Кабинет организатора» → создайте конкурс с темой → создайте ссылки-приглашения →
раздайте участникам → нажмите «Начать приём работ».

## Переменные окружения

| Имя | По умолчанию | Назначение |
|---|---|---|
| `SECRET_KEY` | dev-значение | подпись JWT (**обязательно сменить**) |
| `DATABASE_URL` | `sqlite:///./contest.db` | например `postgresql+psycopg://user:pass@host/db` |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NICKNAME` | admin@example.com / admin12345 | первый организатор |
| `CORS_ORIGINS` | `http://localhost:5173` | список через запятую |
| `TOKEN_TTL_MINUTES` | 10080 (7 дней) | время жизни токена |

## Структура

```
backend/app/
  config.py     настройки, пять шкал и число звёзд (менять шкалы тут + колонки в models.Rating)
  models.py     User, Invite, Contest, Story, Rating, Star, Review
  services.py   смена фаз, случайные номера, подсчёт топов
  deps.py       авторизация, роли, require_phase(...)  ← проверка фазы на сервере
  routers/      auth, contest, stories, voting, results, me (личный кабинет), admin
backend/tests/  фазы, анонимность, звёзды, рецензии, личный кабинет, топы, инвайты

```

## API

| Метод и путь | Фаза | Кто |
|---|---|---|
| `POST /api/auth/register` `{invite_token,email,nickname,password}` | любая | по инвайту |
| `POST /api/auth/login`, `GET /api/auth/me`, `GET /api/auth/invite/{token}` | любая | |
| `GET /api/contest/current` | любая | все (в draft тема скрыта от участников) |
| `GET/PUT/DELETE /api/stories/me` `{title, body, disclaimer}` (название до 200; `body` — HTML из редактора, на сервере очищается по белому списку, видимого текста до 10 000 знаков; дисклеймер до 1000 знаков, необязателен) | PUT/DELETE: submission | участник |
| `GET /api/voting/stories`, `GET /api/voting/stories/{n}` | voting | участник |
| `PUT /api/voting/stories/{n}/rating` (5 полей 1–5) | voting | участник |
| `PUT/DELETE /api/voting/stories/{n}/star` | voting | участник |
| `GET /api/rules` (публичный: текст правил; пока организатор ничего не сохранил, отдаётся стандартный) | любая | все, даже без входа |
| `PUT/DELETE /api/admin/rules` `{body}` (HTML из редактора, очищается по белому списку; до 20 000 знаков; DELETE возвращает стандартный текст) | любая | организатор |
| `PUT /api/voting/stories/{n}/survey` (опросник для статистики: жанры, сеттинги, пол героя, 4 вопроса да/нет; всё необязательно, пустой = удалить; на оценки не влияет) | voting | участник |
| `PUT/DELETE /api/voting/stories/{n}/review` `{body}` (1–5000 символов, одна на рассказ) | voting | участник |
| `GET /api/results`, `GET /api/results/stories` (все работы), `GET /api/results/stories/{n}` (с рецензиями) | results | все |
| `GET /api/me/contests` (архив участий), `GET /api/me/contests/{id}` (рассказ, полученное, отданное) | любая | участник |
| `POST/PATCH /api/admin/contest`, `POST /api/admin/contest/advance` | | организатор |
| `GET /api/admin/stats`, `GET/POST/DELETE /api/admin/invites` | | организатор |

## Как обеспечена анонимность

- В ответах фаз `submission` и `voting` нет ни автора, ни `author_id`, ни id рассказа, ни времени загрузки: только
  `anon_number`. Скрытие не на фронтенде, а в сериализации ответов бэкенда.
- Номера присваиваются **случайно в момент старта оценивания**: порядок номеров не выдаёт порядок отправки.
- Организатор в конкурсе не участвует и авторов до финала не видит через API.
- **Рецензии**: пишутся только в фазе `voting` на чужие рассказы, читаются только в `results`. Автор рецензии
  не раскрывается **никогда**, даже в финале: в ответах только `body` (без id и времени), порядок рецензий
  перемешан. `reviewer_id` в базе нужен лишь для правки/удаления своей рецензии и показа её в кабинете.
- **Личный кабинет** (`/api/me/...`): чужие работы там только под анонимными номерами, псевдонимы авторов
  добавляются лишь для конкурсов в `results`; то, что получил ваш рассказ (оценки, места, звёзды, рецензии),
  скрыто до финала. Организатору кабинет недоступен.
- Тесты проверяют, что в ответах нет псевдонимов, `author`, `created_at`, `updated_at` и внутренних `id`.

Что **не** закрыто (осознанно, для прототипа):
- Участник может сам подписаться в тексте или выдать себя стилем. Это вне власти кода.
- Тот, у кого есть доступ к базе данных, видит авторов. Организатор с доступом к серверу тоже.
- Нет ограничения частоты запросов, капчи, подтверждения email, восстановления пароля.
- Токен хранится в `localStorage`; для продакшена лучше httpOnly-cookie.
- Подсчёт топов делается на лету при каждом открытии результатов; при больших объёмах закешируйте снапшот при переходе в `results`.

## Идеи для следующих шагов

Минимальное число оценок для попадания в топ, учёт «нечестных» крайних оценок, раскрытие авторов рецензий
по желанию самих рецензентов, напоминания по email о дедлайнах, миграции (Alembic) и PostgreSQL.
